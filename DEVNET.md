# Devnet: оставшиеся шаги запуска

Этот документ описывает подготовленную интеграцию, а не подтверждает развёртывание. Не использовать контракт для реальных средств.

1. В среде с Rust, Solana/Agave SBF и Anchor 0.32.1 перейти в `contracts/`, выполнить `anchor build`, `anchor keys sync`, повторить `anchor build` и `cargo test`. Синхронизация заменяет placeholder program ID; нужен собственный program keypair. Ключи не коммитить.
2. Запустить Solana VM / локальный валидатор и добавить/выполнить интеграционные проверки ниже. Rust unit-тесты в репозитории покрывают комиссию и размер аккаунта, но **не являются интеграционными тестами исполнения программы**.
3. Развернуть программу в Devnet выделенным тестовым кошельком, явно указав devnet cluster. Убедиться, что program ID соответствует сборке. Пользовательские основные кошельки для исполнителя не нужны.
4. Пополнить выделенный кошелёк исполнителя тестовыми SOL из devnet faucet. Для начальной настройки он должен быть upgrade authority программы. После развёртывания из корня приложения выполнить:

```sh
npm run setup:devnet -- PROGRAM_ID /absolute/path/to/devnet-only-keypair.json TREASURY_ADDRESS --confirm-devnet
```

Скрипт использует только официальный Devnet RPC, инициализирует Config, регистрирует Автора и Редактора, печатает публичные адреса. Существующие аккаунты не перезаписывает. Скрипт ещё не запускался против развёрнутой программы.

5. В секретах серверного окружения задать `OPENAI_API_KEY`, `AI_MODEL`, `EXECUTOR_SECRET` (JSON-массив 64 байт из выделенного **тестового** ключа). Публичные настройки: `SOLANA_PROGRAM_ID`, `EXECUTOR_ADDRESS`, `TREASURY_ADDRESS`, `AUTHOR_AGENT_ADDRESS`, `EDITOR_AGENT_ADDRESS`. Не использовать `NEXT_PUBLIC_*` для секретов. Локально скопировать `.dev.vars.example` в `.dev.vars` и заполнить в своём редакторе. Не отправлять ключи в чат. На Sites использовать настройки секретов проекта; ключ OpenAI можно подключить через официальный OpenAI Developers plugin.
6. Проверить отдельный AI-вызов выбранной модели и полный путь в Devnet. Только после этого включить `DEVNET_ENABLED=true`.

## Обязательные интеграционные проверки перед включением

- Config может впервые создать только upgrade authority программы; посторонний адрес отклоняется.
- Регистрация услуги сохраняет владельца, цену, тип и описание; адрес PDA зависит от владельца и UID.
- Открытие заказа переводит точную сумму в escrow; недостаточный баланс отклоняется атомарно.
- Посторонний исполнитель, подменённый получатель или treasury не могут завершить заказ.
- До дедлайна авторизованная выплата отправляет `amount-fee` исполнителю и `fee` treasury.
- Повторная выплата, возврат после выплаты и выплата после возврата отклоняются.
- Возврат до дедлайна отклоняется, после дедлайна доступен только покупателю.
- Два конкурентных запроса на завершение не дают две выплаты.
- Одна оценка 1–5 только от покупателя завершённого заказа; повторная и чужая оценки отклоняются.
- Подзаказ оплачивается из бюджета исполнителя, а не дополнительным списанием с покупателя.
- Восстановление после неподтверждённого RPC-ответа сверяет состояние escrow, а не отправляет новую выплату вслепую.
- Подмена серверного результата обнаруживается по хешу в завершённом аккаунте.

## Что не вошло

SPL-токены, mainnet, арбитраж качества, запуск стороннего кода, автономный планировщик, защита репутации от Sybil, автоматический сбор rent и просроченных подзаказов. Для публичного многопользовательского запуска нужны аудит контракта, лимиты по IP/аккаунту на уровне edge и эксплуатационный мониторинг.
